# 1.0.10 BackgroundAnalyzer textured 배경 타입 제거 및 complex_pattern 흡수 (5타입 → 4타입)

---

## (사용할 skills: feature-dev)

## 개요

전체 데이터셋(12,568장) Stage 0 분석 결과 `textured` 배경 타입이 전체 BG 셀의 0.54%(6,787/1,256,800)에 불과하고,
subtype_bg_matrix 상 호환성 점수도 전 서브타입에서 0.0015~0.0088 (사실상 0)임을 확인했다.
통계적 유의성과 분류 실익이 없으므로 `textured`를 제거하고 `complex_pattern`으로 흡수, 4-type 체계로 전환한다.
변경 후 BG 타입: `smooth` / `complex_pattern` / `vertical_stripe` / `horizontal_stripe`.
v/h stripe 통합은 방향성 신호 실재(linear_scratch에서 v_stripe 3.3×, irregular에서 h_stripe 6.5×)를 근거로 별도 분리 유지.

---

## 영향도 분석

### 이 기능이 변경하는 상태
- `BackgroundType` enum에서 `TEXTURED` 멤버 소멸
- `classify_patch()` 반환값에서 `TEXTURED` 경로 2곳 → `COMPLEX_PATTERN` 흡수
- `BG_TYPES` 상수 5 → 4개, 이를 참조하는 행렬 차원·figure 축·fallback 비율 전파
- `MATCHING_RULES`에서 `textured` 키 제거 (roi_suitability, build_defect_templates 각각)
- `recommended_config.yaml`, `subtype_bg_matrix_5x5.json`, `defect_bg_matrix_4x5.json` 재생성 시 textured 컬럼 사라짐

### 그 상태를 전제로 동작하는 기존 로직
- `extract_rois.py` — `--config`로 `recommended_config.yaml` 소비. textured 키 의존 없음 (config_loader에 textured 참조 없음)
- `Stage B/C` — compatibility_matrix를 YAML에서 읽음. textured 키 없어도 동작
- `build_defect_templates.py` — MATCHING_RULES 문자열 리터럴로 직접 사용. 동시 수정 필수
