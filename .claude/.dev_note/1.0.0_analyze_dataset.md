## 개요

현재 CASDA 파이프라인의 DefectCharacterizer·BackgroundAnalyzer·파라미터 등 19개 임계값이
근거 없이 하드코딩되어 있다. 전체 Severstal 데이터셋을 분석하는 `scripts/analyze_dataset.py`를
신규 작성하여 실제 데이터 분포에서 임계값을 도출한다. 이 스크립트는 파이프라인 Stage 0으로,
Stage A~C의 모든 파라미터가 이 분석 결과에 기반한다.

**입력 인자**
```
--image_dir      TRAIN_IMAGES 경로  (/content/drive/MyDrive/data/Severstal/train_images)
--train_csv      TRAIN_CSV 경로     (/content/drive/MyDrive/data/Severstal/train.csv)
--output_dir     ANALYSIS_DIR 경로  (/content/drive/MyDrive/data/Severstal/analysis)
--num_workers    병렬 워커 수 (기본: os.cpu_count() or 2)
--max_images     분석할 최대 이미지 수 (기본 전체, 디버그용)
```

**처리 흐름**

```
1. train.csv 로드 → ImageId별 결함 RLE 디코딩 → binary mask 생성
2. 결함 없는 이미지 목록 식별 (find_clean_images 방식)

3. [결함 분석] 모든 결함 인스턴스 순회:
   - skimage.measure.regionprops로 connected component 추출
   - DefectCharacterizer로 linearity / solidity / aspect_ratio / fill_ratio 산출
   - class_id + defect_subtype 기록 → morphological_features.csv

4. [배경 분석] 모든 이미지 순회 (결함 있는 이미지 포함):
   - 64px 그리드 패치 단위로 variance / edge_strength / high_freq_ratio 산출
   - BackgroundAnalyzer.classify_patch() 호출 → background_type 분류
   - 패치별 특성값 기록 → background_features.csv

5. [4×5 매트릭스] 결함 인스턴스별 (class_id, background_type) 공출현 집계
   - background_type은 해당 결함 ROI 위치의 그리드 셀 다수결로 결정
   - 셀별: count_real, target_synthetic (imbalance 보정), compatibility_score 계산
   → defect_bg_matrix_4x5.json

6. [임계값 도출] 각 feature 분포에서 후보 임계값 산출:
   - 히스토그램 valley 탐지: scipy.signal.find_peaks (inverted histogram)
   - 백분위수: P10 / P25 / P50 / P75
   → threshold_recommendations.json

7. [권장 설정] threshold_recommendations.json 기반으로 recommended_config.yaml 생성
   - 19개 교체 대상 파라미터 전체 포함
```

**출력 파일 목록**

| 파일 | 내용 |
|------|------|
| `class_distribution.json` | 클래스별 인스턴스 수, 이미지당 빈도, 희귀 클래스 판단 기준 후보 |
| `morphological_features.csv` | 인스턴스별 class_id, defect_subtype, linearity, solidity, aspect_ratio, fill_ratio |
| `background_features.csv` | 패치별 image_id, bg_type, variance, v_strength, h_strength, high_freq_ratio |
| `defect_bg_matrix_4x5.json` | 4×5 셀별 {count_real, target_synthetic, compatibility_score} |
| `threshold_recommendations.json` | 19개 파라미터별 {current, valley, p25, p50, p75, recommended} |
| `recommended_config.yaml` | Stage A~C 스크립트에 바로 전달 가능한 파라미터 파일 |
| `analysis_report.md` | 텍스트 분포 요약 + 임계값 근거 서술 + figures/ PNG 경로 참조 |
| `figures/*.png` | 클래스별·feature별 히스토그램, 4×5 매트릭스 heatmap |

- `src.analysis.background_characterization.BackgroundAnalyzer`
- RLE 디코딩: 기존 `extract_rois.py` 또는 `src/` 내 유틸 확인 후 재사용

**현재 하드코딩된 호환성 표 (개선 대상) — `src/analysis/roi_suitability.py:MATCHING_RULES`**

| Defect Type    | Smooth | Vert. Stripe | Horiz. Stripe | Textured | Complex |
|----------------|--------|-------------|--------------|----------|---------|
| linear_scratch | 0.7    | 1.0         | 1.0          | 0.5      | 0.3     |
| compact_blob   | 1.0    | 0.5         | 0.5          | 0.7      | 0.6     |
| irregular      | 0.6    | 0.5         | 0.5          | 0.8      | 1.0     |
| general        | 0.7    | 0.7         | 0.7          | 0.7      | 0.7     |

> 이 수치는 논문에서 도메인 지식 기반으로 **수동 설정한 값**이다.  
> analyze_dataset.py 목적: 전체 데이터셋 실제 공출현 분포를 분석하여 이 표의 수치를 **데이터 기반으로 교체**한다.

**4×5 target_synthetic 산출 공식**

실제 구현 (`analyze_dataset.py:build_matrix_and_params()`):
```python
# 전체 배경 타입 marginal distribution (모든 클래스 합산)
global_bg = M.sum(axis=0) / M.sum()         # shape (5,)

# 클래스별 실제 배경 분포
P[c] = M[c] / M[c].sum()                    # shape (5,)

# deficit: 글로벌 분포 대비 해당 클래스의 부족분 → 희소 조합일수록 높음
deficit = clip(global_bg - P[c], 0)

# target_synthetic: deficit을 정규화한 합성 비중 (0~1, 합=1)
target_synthetic[c][bg] = deficit[bg] / deficit.sum()
```

**compatibility_score 산출 — 데이터 기반 개선 목표**

현재 코드(`analyze_dataset.py`)는 논문 prior와 실측 비율을 혼합:
```python
compatibility_score = 0.6 * MATCHING_RULES[subtype][bg]  # 논문 prior
                    + 0.4 * empirical_P[c][bg]            # 실측 공출현 비율
```

**개선 방향**: analyze_dataset.py 분석 결과를 통해 MATCHING_RULES 수치 자체를 교체:
```python
# 실측 공출현 비율 → 정규화 → 새 compatibility_score
# (논문 prior 가중치를 줄이거나 제거하고 데이터 기반 값으로 대체)
empirical_compat[subtype][bg] = count_real(subtype, bg) / count_real(subtype, all_bg)

# recommended_config.yaml에 출력 → MATCHING_RULES 교체 근거 제시
```

> **핵심 목적**: 현재 수동 설정 표(0.7/1.0/0.5 등)가 실제 철강 데이터 분포와 일치하는지 검증하고, 불일치 시 데이터 기반 수치로 교체한다. 이는 리뷰어 지적 "임계값 결정 근거 불충분"에 대한 직접 대응이다.

> `elongated`는 코드에만 존재 (논문 미기재). 분석 시 general로 통합 또는 별도 집계.

**valley 탐지 로직**
```python
counts, bin_edges = np.histogram(values, bins=50)
inverted = counts.max() - counts
peaks, _ = scipy.signal.find_peaks(inverted, prominence=counts.max() * 0.1)
# peaks → valley 위치 → bin_edges[peaks] → 임계값 후보
```

## 암묵적 요구사항

- 결함 없는 이미지도 배경 분석 대상 포함 (배경 분포 편향 방지)
- 결함 인스턴스가 0개인 클래스 처리 (division by zero 방지)
- 이미지 로드 실패 시 경고 후 건너뜀 (전체 중단 없음)
- `--max_images` 옵션으로 소규모 테스트 지원
- 이미 `output_dir`에 결과가 있으면 덮어쓰기 (재실행 가능)
- 멀티프로세싱: 이미지 단위 병렬화, workers=min(os.cpu_count(), 8) 기본값
- **메모리 (Colab Pro ~25GB)**: 이미지 순차 처리 권장, 결과 누적은 dict/list로 충분
- **시각화 (Colab)**: matplotlib backend='Agg', figures/ 하위 PNG 저장 (Drive에서 확인)
- tqdm 진행바: Colab 호환 (`tqdm.auto` 사용)
