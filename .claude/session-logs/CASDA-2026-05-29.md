## Mask-to-defect alignment (IoU) 설명

### 문제 배경

Stage B에서 ControlNet이 이미지를 생성할 때, **힌트 이미지의 R채널**(원본 결함 마스크)을 conditioning으로 사용합니다. 즉 "이 위치에 이런 형태의 결함을 만들어라"고 지시합니다.

그런데 ControlNet은 확률적 생성 모델입니다. **지시한 위치·형태와 실제 생성된 결함 위치·형태가 다를 수 있습니다.**

```
힌트 R채널 (GT mask)     생성된 이미지
┌──────────┐             ┌──────────┐
│          │             │          │
│  ████    │  →  생성  → │   ████   │  ← 위치 이동
│          │             │          │
└──────────┘             └──────────┘
```

### 무엇을 측정하는가

```
IoU = (GT_mask ∩ detected_defect_region) / (GT_mask ∪ detected_defect_region)
```

- **GT mask**: 힌트 R채널 (원본 결함 이진 마스크)
- **detected_defect_region**: 생성 이미지에서 실제 결함이 나타난 영역 (엣지 검출 또는 thresholding으로 추정)

### 왜 중요한가

CASDA의 생성 이미지는 **학습 데이터**로 사용됩니다. 이때 annotation mask는 GT mask를 그대로 씁니다.

```
IoU가 낮으면:
  실제 결함 위치 ≠ 어노테이션 마스크 위치
  → 학습 데이터에 잘못된 레이블 포함
  → 모델이 잘못된 위치를 결함으로 학습
  → benchmark 성능 저하 원인이 측정되지 않음
```

### FID/KID와의 차이

| 지표 | 측정 단위 | 측정 내용 |
|------|---------|---------|
| FID / KID | 분포 수준 | 생성 이미지 전체 분포가 실제와 얼마나 유사한가 |
| LPIPS | 이미지 쌍 수준 | 두 이미지의 perceptual 유사도 |
| **Mask-IoU** | **이미지 쌍 수준** | **생성된 결함이 지정된 위치에 실제로 있는가** |

FID가 높아도 Mask-IoU가 낮을 수 있습니다 — 분포는 그럴듯하지만 개별 이미지에서 결함이 엉뚱한 곳에 생성된 경우.

### Stage C 이후 추가 검증 포인트

Poisson Blending 후에도 동일 측정 가능:

```
Blending 전: 512×512 생성 ROI에서 GT mask vs 실제 결함 위치 IoU
Blending 후: 1600×256 합성 이미지에서 배치된 마스크 vs 결함 경계 IoU
```

두 번째 측정은 Blending 과정에서 경계가 번지거나 결함이 흐려지는 현상도 포착합니다.

### Stage 0과의 연계

Stage 0에서 원본 데이터셋의 마스크 품질 기준값(실제 결함 마스크 edge precision)을 먼저 산출하면, 생성 이미지의 Mask-IoU 허용 하한을 데이터 기반으로 설정할 수 있습니다.
